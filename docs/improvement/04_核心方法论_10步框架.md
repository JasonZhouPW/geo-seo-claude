## Phase 1：技术准备

### 步骤 1：robots.txt 审查

**目的**：确保 AI 爬虫可以访问你的内容

| 爬虫名称 | 运营商 |
|----------|--------|
| GPTBot | OpenAI (ChatGPT) |
| ClaudeBot | Anthropic (Claude) |
| PerplexityBot | Perplexity |
| GoogleOther-bot | Google (AI Overviews) |
| CCBot | Common Crawl |

**检查清单**：
```txt
# ❌ 错误示例（阻止了 AI 爬虫）
User-agent: GPTBot
Disallow: /

# ✅ 正确示例（允许 AI 爬虫）
User-agent: GPTBot
Allow: /
```

**操作**：在 Google Search Console 或直接访问 `yourdomain.com/robots.txt` 检查。

---

### 步骤 2：Schema Markup 实施

**目的**：用结构化数据帮助 AI 理解内容上下文

| Schema 类型 | 适用场景 | 优先级 |
|-------------|----------|--------|
| **Article** | 新闻文章、博客文章 | 🔴 高 |
| **Organization** | 品牌信息 | 🔴 高 |
| **FAQPage** | 问答内容 | 🔴 高 |
| **HowTo** | 操作指南、教程 | 🟡 中 |
| **Product** | 电商产品 | 🟡 中 |
| **BreadcrumbList** | 页面层级 | 🟡 中 |
| **LocalBusiness** | 本地商户 | 🔴 高（本地商户） |
| **Person** | 创始人/专家 | 🟢 推荐 |

**FAQPage 示例（JSON-LD）**：
```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "什么是 GEO？",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "GEO（生成式引擎优化）是一种优化内容在 AI 搜索引擎中被引用的策略。"
    }
  }]
}
```

**工具推荐**：
- Google Rich Results Test（验证 schema 是否有效）
- Schema Markup Generator（Merkle 或 Rank Ranger）

---

### 步骤 3：llms.txt 考虑

**背景**：`robots.txt` 告诉爬虫什么可以访问，`llms.txt`（新兴标准）告诉 AI 如何理解你的网站。

**现状**：目前属于早期采用阶段，2026 年逐步有平台开始支持。

**操作**：如果你的内容有复杂的层级结构，可以考虑添加 `https://yourdomain.com/llms.txt`，提供 AI 可读的站点说明。

---

### 步骤 4：站点性能与移动端

| 指标 | GEO 要求 | 说明 |
|------|----------|------|
| 页面速度 | Core Web Vitals 通过 | 仍然是基础 |
| 移动端适配 | 必须 | AI 索引优先移动端 |
| HTTPS | 必须 | 安全信号 |
| 可爬取性 | 无阻止 | 与传统 SEO 相同 |

## Phase 2：内容优化

### 步骤 5：Answer-First Design（答案优先设计）

**核心原则**：把结论放在每个段落/章节的最前面。

**为什么重要**：
- AI 按 passage 评估内容（不总是读完整页）
- 倒金字塔结构（Journalism Inverted Pyramid）天然适配 AI 提取
- AI 查询平均 23 词，内容需匹配实际提问方式

**操作模板**：

```
❌ 传统写法（先铺背景）：
"在当今数字营销领域，有很多关于 SEO 和 GEO 的讨论。
SEO 是搜索引擎优化的缩写，而 GEO 是生成式引擎优化..."

✅ Answer-First 写法（先给答案）：
"GEO（生成式引擎优化）是一种让内容在 AI 回答中被引用的优化策略。
它与 SEO 的核心区别在于：SEO 优化排名，GEO 优化引用..."

【然后再展开详细背景和细节】
```

**两句话测试**：对于每个关键段落，问自己——"AI 能用两句话概括这个段落的要点吗？"如果不能，内容结构需要调整。

---

### 步骤 6：统计与数据支撑

**学术依据**：Princeton 研究证明，Statistics Addition 是最有效的 GEO 方法，提升超 40%。

**具体操作**：

| 数据类型 | 示例 | 价值 |
|----------|------|------|
| 行业统计 | "2026 年 AI 搜索占比已超 60%" | 直接可引用 |
| 调查数据 | "我们的客户调查显示，X 指标提升 35%" | 原生数据，独有 |
| 案例数字 | "帮助 500+ 电商提升转化率" | 具象化信任 |
| 行业排名 | "在 Gartner MQ 中排名第 3" | 第三方背书 |
| 对比数据 | "X 比 Y 快 40%" | 比较基础 |

**优先生产原创数据**：
- 客户满意度调查
- 行业趋势分析
- 内部案例研究
- A/B 测试结果

---

### 步骤 7：结构化内容块

**原则**：每个内容块独立可理解，AI 可以单独提取和引用。

**操作要点**：

```
标题（H2/H3）：清晰概括本节核心观点
         ↓
段首句：直接回答本节要解决的问题
         ↓
支撑内容：2-4 句展开
         ↓
可视化（可选）：表格、列表、数据图
         ↓
小结（可选）：1 句话重申核心
```

**FAQ 格式直接匹配 AI 问答**：
- 用户在 AI 平台的提问方式 = FAQ 格式
- FAQ schema 让内容同时被人类和 AI 理解

---

### 步骤 8：实体与语义优化

**概念**：实体 = 品牌、产品、人、地点等有明确身份的"名词"。

**实体优化的三个层次**：

| 层次 | 操作 | 说明 |
|------|------|------|
| **识别** | 明确内容中涉及哪些实体 | 品牌名、产品名、竞品名、行业术语 |
| **关联** | 建立实体之间的关系 | "X 是 Y 的竞品"，"Z 由 X 创始人创立" |
| **一致** | 全篇统一实体的名称和描述 | 避免同一实体不同叫法 |

**内部链接的语义优化**：
```
传统 SEO 内链逻辑：相关内容互链
         ↓
GEO 语义内链逻辑：实体关系型链接

示例关系类型：
- 比较型："/X-vs-Y" → AI 理解 X 和 Y 是竞品
- 用途型："/X-for-startups" → AI 理解 X 的目标用户
- 替代型："/alternatives-to-X" → AI 理解 X 存在可替代选项
```

## Phase 3：权威建设

### 步骤 9：Digital PR 与第三方引用

**核心认知**：AI 引擎偏好**第三方背书**，而非自有内容自说自话。

```
AI 的引用偏好：
第三方报道（新闻、评测） > 行业引用 > 自有官网内容
        ↓
Digital PR = 直接 GEO 杠杆
```

**高权重来源类型**：
| 来源类型 | 权重示例 | 说明 |
|----------|----------|------|
| .gov 网站 | 极高 | 政府机构 |
| .edu 网站 | 极高 | 学术机构 |
| 主流媒体 | 高 | Forbes, TechCrunch 等 |
| 行业媒体 | 高 | 垂直行业领导媒体 |
| 独立评测机构 | 高 | 客观第三方 |
| 客户评价/UGC | 中 | 用户生成内容 |

**Digital PR 实操方向**：
- 行业趋势评论（作为专家发声）
- 原创调研报告发布
- 与评测媒体合作
- 播客/视频采访
- 行业奖项申报

## Phase 4：测量与迭代

### 步骤 10：持续监控与优化

**核心 GEO 指标**：

| 指标 | 定义 | 测量方式 |
|------|------|----------|
| **Citation Frequency** | 品牌被 AI 引用的次数 | 定期手动测试 + 工具监控 |
| **Brand Visibility** | 在特定查询的 AI 回答中出现比例 | 工具追踪 |
| **AI Share of Voice** | 品牌引用占同类品牌引用的比例 | 工具追踪 |
| **Position in Answer** | 在 AI 回答中的引用位置（越前越好） | 手动记录 |

**跨平台测试频率建议**：

| 平台 | 测试频率 | 特别要求 |
|------|----------|----------|
| ChatGPT | 每2-4周 | 需要 OpenAI 账号 |
| Perplexity | 每周 | 每日索引，需频繁更新内容 |
| Google AI Overviews | 每月 | 与 Google 索引同步 |
| Bing Copilot | 每2-4周 | 与 Bing 索引同步 |

**内容新鲜度策略**：
- Perplexity 用户：每周检查，优先更新"Top"/"Best"类页面
- evergreen 内容：至少每年刷新一次
- 新闻事件类：实时更新

## 快速执行清单

```
□ 检查 robots.txt（允许 AI 爬虫）
□ 添加 Article + FAQPage schema（核心页面）
□ 将 3-5 篇核心内容改为 Answer-First 结构
□ 加入统计数据（至少每篇 2-3 个具体数字）
□ 统一实体名称和关联描述
□ 用 ChatGPT/Perplexity 测试核心品牌查询
□ 记录当前引用情况（基线）
□ 安排每月定期复测
```
